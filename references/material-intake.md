# 材料准入与难转材料处理

> 对象不是总有干净文本。扫描件、加密 PDF、动态网页、监控视频、微信聊天导出、旧版 Office、GBK 编码的日志——这些东西读不到不等于对象没内容，读到了也不等于读对了。这一层要解决的是「证据从哪来、缺的部分怎么诚实交代」。

## 0 三条前提

1. **转换失败 ≠ 对象无内容**：只说明这条通道拿不到，必须换通道或登记缺口。
2. **读到了 ≠ 读对了**：OCR 会把 `0` 读成 `O`，表格合并单元格会丢列，聊天导出会缺上下文；凡转换件都要标误差来源。
3. **读了 ≠ 可引用**：没有行号、页码、时间戳的转换结果，只能当线索，不能挂 `[O]` 锚点。

## 1 准入四问（S3 采集前逐問）

| 问 | 不合格的表现 | 处置 |
|---|---|---|
| 能不能读？ | 0 字节、乱码、打不开、要密码 | 换源或转码；仍不行走出口 D/E |
| 读了算不算一手？ | 只有二手转述、百科、营销稿 | 顺引用回溯原文；找不到就标「一手未获取」 |
| 读完能不能定位？ | 没有页码/行号/时间戳 | 先做可定位的转换（PDF 页码、逐字稿时间戳） |
| 不能读时有没有替代源？ | 只有这一个链接 | 官方 HTML/API、镜像、作者其他版本、监管披露文件 |

**够用标准**：能引出一句原文 + 能指回一个位置 + 能说明这是谁在什么时间说的。三条缺一条，就不是 `[O]`。

## 2 分型处理表

| 材料 | 首选 | 备选 | 够用判据 | 禁令 |
|---|---|---|---|---|
| Markdown / 纯文本 | 直读，UTF-8 | 转码 GB18030 | 行号可定位 | 不许按乱码摘句 |
| PDF 有文本层 | `pdftotext -layout` | PyMuPDF 取块 | 能对上页码 | 不许只读摘要页就下结论 |
| PDF 扫描件 | OCR（标明引擎与语言） | 人工核对关键数字 | 关键数字逐字复核 | 不许把 OCR 结果当原文引用 |
| 加密 / 权限 PDF | 找官方原版 | 找监管/法院公开版本 | 来源可核 | 不许破解；解不开就登记 |
| Word `.docx` | 解压读 `document.xml` | pandoc 转 md | 段落与修订都在 | 不许忽略 `w:ins/w:del`（修订稿常藏关键改动） |
| 旧 `.doc` / `.xls` | LibreOffice 转新格式 | 在线只读预览 | 抽查 3 处与合计 | 不许假设转换无损 |
| Excel 多 sheet | openpyxl 逐表读值 | 导出 CSV 分表 | 公式与值分开记 | 不许只读第一个 sheet |
| PPT | 逐页文本框 + 备注 | 导出 PDF 再取文本 | 页码可定位 | 图上的字要另做 OCR |
| 图片（截图/扫描） | OCR + 视觉读图 | 找原始文档 | 关键字段人工复核 | 不许从照片推断动机 |
| 图表图片 | 读数轴、单位、图例 | 找数据源 | 数字与源表一致 | 不许只写「呈上升趋势」 |
| 网页（静态） | 抓 HTML 存快照 | 官方 API | 带抓取时间 | 不许引用会变的页面而不存快照 |
| 网页（动态/登录墙） | 浏览器渲染后存档 | 找公开报告/镜像 | 截图 + 时间 + URL | 不许凭记忆复述页面 |
| 音视频 | 转写 + 时间戳 | 官方字幕/纪要 | 关键结论回听原片段 | 不许把转写当逐字原文 |
| 压缩包 | 先列目录再逐项 | 找单文件原版 | 清单与哈希 | 不许整包当一份材料 |
| 聊天记录/邮件导出 | 按时间序 + 角色标注 | 原始客户端导出 | 保留发送者与时间 | 不许拼接成「他说的」 |
| 代码仓库 | 浅克隆 + 入口文件 | GitHub API 取文件 | commit 短哈希 | 不许拿默认分支当历史 |
| 数据库导出 | 先看 schema 再查 | 只读副本 | 口径与时间窗 | 不许把查询结果当全量 |
| 未知二进制 | 先识别魔数 | 问提供方 | 类型确认 | 不许猜内容 |

机器可判的部分：`python "{skill_root}/scripts/material_audit.py" <产物根>` 会列出空文件、非 UTF-8、需转换的二进制、可疑未知文件、超大文本，并给每类一行处理路线。它只报「能不能读」，不判「内容对不对」。

## 3 五个出口（转换失败时必须选一个，不许沉默）

| 出口 | 什么时候用 | 怎么写 | 禁止 |
|---|---|---|---|
| **A 拒收** | 对象核心材料全都拿不到，或拿到的只有二手转述 | frontmatter `decision: refuse`，正文写「为什么蒸不了 + ≥3 条能判真假的理由」 | 声明拒收却产全套模板节 |
| **B 降级** | 只拿到结构/目录级信息，拿不到内容 | 产物标题标「结构级」，结论只到「有什么、怎么组织」，不写「为什么」 | 把目录当内容、把标题当论点 |
| **C 换源** | 原链接受限，但存在官方/镜像/公开披露 | 证据台账记两个来源与差异；以更权威的一份为准 | 拿二手转述替代原文还标 `[O]` |
| **D 抽样** | 材料量过大（几百份合同、上千条日志） | 写明抽样规则、样本量、未覆盖部分；结论标「样本内成立」 | 用样本结论覆盖全量 |
| **E 挂起** | 暂时解不了，但不影响主结论 | 未知台账写「缺什么、为什么解不了、需要什么才能解」 | 把「没找到」写成「不存在」 |

## 4 行业场景矩阵（按常见材料形态归类，不是行业统计）

| 角色 | 常见难转材料 | 先用什么 | 替代源 | 不许下什么结论 |
|---|---|---|---|---|
| 律师 | 扫描判决书、盖章合同、庭审录音 | OCR + 逐字稿；关键条款人工复核 | 法院公开文书、裁判文书网 | 不许凭 OCR 错字解释条款含义 |
| 医生 | 检验单照片、影像报告 PDF、病历导出 | OCR + 结构化字段；单位与参考区间单独核 | 医院官方报告、指南原文 | 不许跨报告拼接成诊断结论 |
| 财务/审计 | 多 sheet 底稿、PDF 财务报表、凭证扫描 | 逐表读值 + 报表勾稽 | 年报/审计报告原文 | 不许用截图数字当账面数 |
| 工程师 | 超大仓库、二进制固件、日志压缩包 | 浅克隆 + 入口文件；日志先解压列目录 | 官方文档、release 说明 | 不许拿默认分支当历史、拿日志猜架构 |
| 教师 | 教材 PDF、课件 PPT、手写作业 | 文本层优先；手写走 OCR | 出版社样章、课程大纲 | 不许把 OCR 结果当学生原话 |
| 科研 | 论文补充材料、数据集、预印本 | 原文 PDF + 数据字典 | 期刊官网、OSF/Zenodo | 不许只读摘要就评价方法 |
| 产品/运营 | 后台截图、竞品页面、用户访谈录音 | 截图存档 + 转写 | 帮助中心、公开 API | 不许凭一次截图断言产品能力边界 |
| 设计 | 设计稿、字体包、品牌手册 | 导出 PNG/PDF 看层级 | 品牌官网、发布稿 | 不许从截图推断设计决策理由 |
| 政务 | 红头文件扫描、公示 PDF、会议纪要 | OCR + 文号核对 | 政府公报、官网原文 | 不许脱离文号与生效日期引用 |
| 媒体 | 采访录音、聊天截图、通稿 | 转写 + 原始截图留存 | 发布原文、当事方声明 | 不许把二手转述当采访原话 |
| HR | 简历批量 PDF、测评报告 | 批量提取 + 字段对齐 | 候选人原件、测评机构说明 | 不许用抽取错误给人下判断 |
| 供应链/制造 | 图纸 PDF、BOM 表、检验记录 | 图纸读标注；BOM 逐行核 | ERP 导出、质检原始记录 | 不许用汇总表替代原始记录 |

## 5 转换件的写法（正文四行，缺一不可）

```markdown
## 材料与转换
- 读了什么：<类型 + 数量 + 来源>，其中一手 <N> 份、二手 <M> 份
- 怎么转的：<工具/命令>，误差来源：<OCR/表格合并/转写断句…>
- 没转成什么：<文件>，原因：<加密/无文本层/登录墙>，已走出口 <A–E>
- 替代源：<官方原文/镜像/披露文件>，与原件差异：<有/无/未核>
```

这四行不是形式：缺「没转成什么」，读者会把缺口当结论；缺「误差来源」，OCR 错字会被当成原文。

## 6 反模式

- 把 0 字节文件当「对象没写这块」——先怀疑下载失败。
- 用 `.md` 之外一律不读：代码、配置、schema 往往才是机制所在。
- OCR 出来就直接挂 `[O]`：转换件只能 `[D]` 或标「OCR 转写，未逐字核」。
- 只读 PDF 前 10 页就写「全文」：页数、章节、附录要交代。
- 拿截图上的数字做计算：截图不是数据源。
- 登录墙页面凭记忆复述：没存档就等于没读。
- 大材料只读开头就下全量结论：抽样必须写规则与样本量。
- 解不开就沉默：五个出口一个都不选，是最糟的处理。

## 7 验收（三条）

1. `material_audit.py` 跑过，问题清单有处置（转换/换源/挂起），不是「知道了但没做」。
2. 正文有「材料与转换」四行，且「没转成什么」不是空的（真全转成了就写「无」）。
3. 任何转换件挂的锚点，能在转换产物里定位（页码/时间戳/行号），不是只指向原文件。
