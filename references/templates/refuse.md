# 模板：refuse（克制型产物）

> 用在该蒸不该蒸这个问题本身：正解是「不蒸」。它不是「产物写短一点」，而是「产出一份能被反驳的拒蒸判断」。

```markdown
---
name: <slug>
description: 判定 <对象> 不值得蒸馏，并说明凭什么这么判。
decision: refuse
source: <读到哪些文件、什么版本、什么日期>
---

# <对象>：不蒸

## 判断
<不蒸 / 只蒸某一层 / 先补材料再蒸——三种结论只能选一种，写清是哪种>

## 理由（至少 3 条，每条要能判真假）
- [O] <从对象自身读到的证据 + 锚点>：说明为什么撑不起一份产物
- [O] <第二条：换一个角度（缺实现 / 缺测试 / 缺调用方 / 只有二手转述）>
- [D] <第三条：与已蒸过的同类对象对比，说明这次同样会失败>

## 未知台账

| 未知 | 为什么解不了 | 需要什么才能解 |
|---|---|---|
| <要蒸它还缺什么> | <为什么现在拿不到> | <材料 / 权限 / 版本> |
```

## 判据（门禁实际在查的）

| # | 判据 | 红线 |
|---|---|---|
| 1 | `refuse-shape` | 正文写齐 ≥4 个模板节 = 声明不蒸却在产全套 → FAIL |
| 2 | `refuse-reasons` | 可判真假的理由 <3 条 → INCOMPLETE |
| 3 | `refuse-marks` | 0 处 `[O]/[D]/[I]` → INCOMPLETE（凭什么说它不值得蒸，要标层级）|
| 4 | `refuse-anchors` | 可解析锚点 <2 个 → INCOMPLETE；锚点不可解析 → FAIL |
| 5 | `section:未知台账` | 缺失 → INCOMPLETE（要蒸它还缺什么，必须写清）|

## 不许拿它当免检

- 拒蒸**不豁免**「读过」这件事：没有锚点就是没读就下结论。
- 拒蒸**不豁免**「为什么」这件事：三条理由以下，等于说不出判断。
- 拒蒸**不豁免**「边界」这件事：正文若写齐正式产物的节，说明你其实在产，只是挂了 refuse 的牌子。
