# 模板：rules（判据型产物）

> 用于事故、失败案例、技能库审计、会议复盘。产物必须是可执行的「触发→禁令→修复→兜底」，不是故事。

```markdown
---
name: <slug>-rules
description: <从 <N> 次失败/审计里抽出的 <M> 条判据，覆盖 <场景>>
source: <事故单/日志/审计报告 + 时间范围>
---

# <主题>判据

|---|---|---|---|---|---|
| 1 | <可观测的触发> | <禁止X> | <先做Y> | <退到Z> | [O] <锚点> |
| 2 | ... | | | | |

## 假阳性排除（哪些情况不算违规）
- <情况 A>：看起来像 <违规>，实际是 <原因>，判据不适用。证据 [O] <锚点>

## 根因层（表象 vs 机制）
- 表象：<症状>
- 机制：<为什么必然发生> [D] <两个锚点>

## 防复发门禁
- 检查项：<哪条命令/断言>
- 反例验证：把 <X> 故意改坏，检查必须变红（附实测结果）
- 静默失效点：<检查可能永远绿的场景>

## 内在张力（不要调和）
- <A 与 B 的冲突>：对象在 <场景> 选 A，在 <场景> 选 B [O] <锚点>
- <它主动接受了哪一条代价>
```
