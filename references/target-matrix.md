# 八类对象的探针表

分诊之后照表执行。每类给：首探针 → 探针序列 → 证据形态 → 常见坑 → 完成标志。

## 1 人（公众人物 / 同事 / 自己）

- 首探针：一手长篇语料（书、完整访谈原文、直播/播客原始音频、真实决策记录）。
- 序列：① 先盘本地素材覆盖哪几维 → ② 只对缺的维补网络搜索 → ③ 抽候选 → ④ 三重验证。
  六维：著作与系统思考 / 长对话与即兴 / 碎片表达 DNA / 他者评价与批评 / 决策记录 / 时间线。
- 证据形态：原话片段 + 出处时间；决策事件 + 当时约束。
- 坑：① 只读二手介绍就下结论；② 把口癖当思想；③ 用知乎/公众号/百科做证据池；④ 同观点出现 <3 次就当核心信念。
- 完成标志：3-7 个心智模型、≥2 对张力、≥3 条具体局限、去名可识别。

## 2 代码仓库

- 首探针：`树` + 入口文件 + `git log -20 --oneline`。
- **前置：先判是否浅克隆**（看 `.git/shallow`）。是则 `git log` 只剩 1 条，拿不到演进信号——改看 `ROADMAP.md` / `CHANGELOG` / releases，并把「只有 N 条提交」写进诚实边界，不许当结论用。`← 第二样本 distilly 11-08`
- 序列：① 读 README 只当门牌，不当初稿 → ② 找入口与调用链 → ③ 逐层读实现（源码 > 文档）→ ④ `git log` 找被反复修的模块（那里是真实复杂度）→ ⑤ 看测试：测什么≈作者认为什么会坏。
- 证据形态：`路径:行`、提交哈希、配置键与其真实默认值。
- 坑：① 只读 README 和 SKILL.md 封面就当学完（真实方法论常在后 2/3）；② 文档说的配置 ≠ 代码实际默认；③ 高星排序会错过严谨但冷门的实现；④ 把注释当事实（注释会腐）；⑤ **把 `bin`/`cmd` 入口当主程序**——入口必须读全文再定性，distilly 的 200 行 CLI 只是安装器，蒸馏流程在 SKILL.md 里；⑥ **只数用例总数就当覆盖充分**——必须把 `test_x` 按模块名映射回源码，distilly 123 个用例下 19 个模块仍有 12 个零覆盖。`← 第二样本 distilly 11-08`
- 反向比对：坑 ② 不只查「文档写了代码没有」，也要查「**代码有硬约束、文档完全没写**」——后者更常见且更危险（用户按文档操作会踩代码里的拒绝分支）。
- 完成标志：能画出入口到副作用的链、能指出 3 条「可搬机制」+ 3 条「明确不搬及理由」、每条都挂 `路径:行`。

## 3 长文档 / 论文

- 首探针：摘要 + 结论段 + 方法段（三段对照，看主张与证据是否对齐）。
- 序列：① 提取主张清单 → ② 每个主张找它对位的证据（表/图/实验）→ ③ 记样本与边界 → ④ 找作者自己承认的局限 → ⑤ 找引用它的批评。
- 证据形态：页码/章节号、表号、样本量、置信区间。
- 坑：① 把综述当原创结论；② 忽略样本边界外推；③ 只读摘要就引用数字。
- 完成标志：主张-证据对应表完整、边界写明、可复现性有判断。

## 4 技能库 / 提示词库

- 首探针：全量 `name + description` 清单与体积分布（description 是常驻成本）。
- 序列：① 算常驻 token 预算 → ② 按 name 前两段聚类找同族，再逐族看触发条件是否重叠 → ③ 查渐进披露第三级资产是否被正文点名 → ④ 查跨层引用死链（先分三桶）→ ⑤ 查触发词是否与真实需求错位。
- 证据形态：文件路径、字节数、description 摘句、被引用次数。
- 坑：① 用技能名判重叠（名字不同、职责相同）；② 把模板占位/通配符当死链（假阳性）；③ 只看「有没有」不看「会不会被加载」；④ 只比对 description 逐字相同就下「无重叠」结论（108 个技能实测 0 组命中，等于没查，真同族有 9 组）；⑤ 一处引用被反引号与裸写各数一遍，死链数虚高。
- 修正（2026-11-09 第二样本，Doubao 客户端 108 技能）：**「用 description 判重叠、不用技能名」这条要反过来理解**——逐字 description 比对只能发现复制粘贴，本库 0 命中；同族靠 name 前缀暴露（doubao-coding-* 8 个、lark 系 20+ 个），再用各自主文件的触发条件核对边界。死链必须先分三桶：真死链（全库找不到，本库仅 1 处）／跨技能引用（文件在兄弟技能下，本库 22 处，属库级约定缺失）／正文举例（本就不该存在，本库 4 处）。
- 完成标志：重叠族名单（按 name 前缀）、常驻预算数字（description 字符合计与均值）、死链三桶清单（含排除依据）。

## 5 事故 / 失败 / 回归

- 首探针：报错原文（完整栈，不截断）+ 最小复现 + 时间线。
- 序列：① 固定现象（何时开始、影响面）→ ② 二分定位（哪个变更引入）→ ③ 根因层：表象（症状）vs 机制（为什么必然发生）→ ④ 修复验证（能证明修好了的最小检查）→ ⑤ 防复发（门禁/测试）。
- 证据形态：栈帧、提交、配置 diff、复现命令与输出。
- 坑：① 用「重启后好了」当根因；② 把最后一个改动当元凶（相关≠因果）；③ 修完不验证就关单。
- 完成标志：一句机制级根因、可重放的复现、能变红的门禁。

## 6 对话 / 会议 / 日志

- 首探针：按时间序 + 角色标注（谁说的、什么身份）。
- 序列：① 切决策点（有分歧/有承诺的位置）→ ② 对账：说过 vs 后来做了什么 → ③ 抽未落地项 → ④ 抽反复出现的卡点。
- 证据形态：时间戳、说话人、原句。
- 坑：① 把讨论当结论；② 把表态当承诺；③ 忽略沉默与「下次再说」。
- 完成标志：决策清单（含谁定、何时定）、未落地项清单、重复卡点 ≥1。

## 7 竞品 / 产品

- 首探针：首屏交互 + 网络请求 + 帮助/定价页。
- 序列：① 走一遍主流程记阻塞点 → ② 抓请求看接口形状与数据字段 → ③ 读定价页找闸门 → ④ 读帮助文档找「官方承认的边界」。
- 证据形态：截图、请求/响应片段、页面文案。
- 坑：① 只看界面不看请求；② 把营销文案当能力清单；③ 假设对方的数据结构与自己一致。
- 完成标志：能力边界表、收费闸门位置、可复刻的最小路径。

## 8 方法论 / 流派

- 首探针：该派代表作 + 该派的批评者（两边都要）。
- 序列：① 抽核心主张 → ② 找它的适用条件 → ③ 找反例与失败案例 → ④ 与相邻流派做差异表（只差在措辞就不是新流派）。
- 证据形态：原文段落、批评原文、反例事件。
- 坑：① 只读拥护者；② 把命名差异当思想差异；③ 忽略它默认的前提（往往就是它的边界）。
- 完成标志：适用/不适用边界、与 2 个相邻流派的差异、≥1 个能击穿它的反例。
