# 证据协议

## 三层标记

| 标记 | 含义 | 判据 | 允许出现在 |
|---|---|---|---|
| `[O]` | 直接观察 | 别人按锚点能复现同一事实 | 任何结论 |
| `[D]` | 合成推导 | ≥2 处 `[O]` 合成，链条可写出来 | 框架、规则 |
| `[I]` | 推断 | 无直接证据，靠类比/常识 | 假设段，**禁止**出现在「必查结论」 |

写法：结论 → 空格 → 标记 → 锚点。

```
入口在 `src/index.ts:42` 注册了 3 条路由 [O] src/index.ts:42-58
该仓库把限流放在中间件而非路由层 [D] src/app.ts:31 + src/http/mw/ratelimit.ts:12
作者倾向「先落地再补测」 [I] 据 3 次提交模式推断，未验证
```

## 锚点格式

| 对象 | 锚点 |
|---|---|
| 代码 | `E-xxxxxxxx`（首选，查指纹）或 `路径:行` / `路径:起-止` |
| 提交 | `commit 短哈希` |
| 网页 | 完整 URL（禁止站点根/搜索页/主题页充数） |
| 文档/论文 | `文件 §章节` 或 `p.页码` |
| 对话 | `时间戳 + 说话人` |
| 数据 | `文件 + 行号/字段` |

一个结论一个主锚点；`[D]` 至少两个锚点。

**同一处锚点重复写不凑数**——门禁按去重计数，写 8 遍仍算 1 处。

### 路径锚点只在这三种情形用

| 情形 | 例子 |
|---|---|
| 迁移期老产物还没换 id | 上一版产物尚未跑 `anchorize` |
| 外部 URL 取不到原文 | 网页快照、已删除的仓库 |
| 该处只出现一次且不跨产物 | 只在未知台账写一次「待补读 `raw/x.md:344`」 |

其余一律用 `E-xxxx`。交付前跑 `distill gate <产物> --strict-anchor` 检查 E id 占比是否 ≥50%。

「待补读某文件某行」这类**指路不是证据**：不该被 `anchorize` 收进证据库，也不该配 `[O]`。

**锚点必须唯一可达（v1.1 硬纪律）**：存在多份同名文件（多个仓库都有 `README.md` / `SKILL.md`）时，必须写全相对路径 `raw/<repo>/README.md:44`。只写 `README.md:44` 会被门禁判「歧义」并 FAIL——因为机器无法确认你指的是哪个仓库，而指向错的仓库比没有锚点更危险。

**锚点不许越界（v1.3 硬纪律）**：不许写 `../` 跳出去，也不许写绝对路径。锚点解析出的文件必须落在产物目录之内，否则判「越界」FAIL——门禁不替你去读产物外的系统文件，那不叫证据，那叫充数。

## 证据条目

读到关键段落就存一条，别等写完再补：

```bash
python scripts/distill.py evidence add --dir out/distill-x \
  --path raw/repo/SKILL.md --lines 14-17 --level O \
  --statement "加载技能不等于授权跑全流程" --source commit:5bb9b65
```

- id 由 `文件|行段|层级` 复算，稳定可重建；同一片段跨产物复用同一个 id。
- `quote_sha1` 是行段原文的归一化指纹，原文变了就转 `changed`，产物必须重读改断言。
- `index` 只回填 `supports`，不改写已有条目；`--dry-run` 只打印不落盘。
- 迁移老产物：`python scripts/migrate_legacy.py --project out/distill-x`，它只读产物不改正文。

## 未知台账

格式固定为三列，缺一列不算登记：

```
| 未知 | 为什么解不了 | 需要什么才能解 |
|---|---|---|
| 该作者 2019 年前的观点 | 无公开存档 | 其早期博客镜像或纸媒访谈 |
```

- 覆盖缺失 ≠ 事实缺失。写「本次未覆盖」，不写「不存在」。
- 「没搜到」只能进台账，不能变结论。
- 台账条目 ≥3 条才算过「未知测试」。

## 覆盖≠存在（三条硬规则）

1. 部分来源里没匹配到，不能证明整个对象没有。
2. 候选覆盖不等于全集（抽了 10 个模块不代表只有 10 个）。
3. 对比要完整对等页集才能声称「等价」或「缺失」；不对等只能写「在已比对部分中」。

## 外部来源分级与冲突台账

> 外部材料的作用是**发现盲区**，不是提供正确答案。任何单一外部来源都按「待验证线索」对待，
> 不许直接当成结论。口径：一手定对错，第三方找疑点，实测做终审。

### 来源三级（禁止平行对待）

| 级别 | 来源 | 作用 | 采纳条件 |
|---|---|---|---|
| L1 一手 | 仓内代码与文档、可复现的 issue、本地实测 | 定对错 | 直接进结论 |
| L2 第三方审计 | 带方法与证据链的安全审计、可复现横评 | 给疑点 | 必须回 L1 验证后才进结论 |
| L3 媒体/博客 | 教程、资讯、个人评测、厂商基准 | 只作线索 | 默认降权，验证不了只记「待验证」 |

- 赞助内容、竞品互踩、官方自报效应量（如「快数百倍」）一律 L3，并标注动机；效应量必须核对评测口径。
- 转载、洗稿同一篇的多个页面算同一个来源，不构成多源。

### 采纳规则（四条硬规则）

1. 外部说法只有能回到 L1 验证（具体文件、端点或复现步骤）才进结论；回不去的只进未知台账，标「待验证」。
2. 同一结论至少两个**真独立**来源；同源转载不算独立。
3. 第三方冲突时禁止投票，回 L1 或自己实测裁决（例：某项目「核心三命令」有两个二手版本，以仓内对照表为准）。
4. 检索无有效结果时写「未做对照」，禁止默认成「外部无异议」。

### 冲突台账（每条外部说法一行，落 `notes/` 下）

| 说法 | 来源/级别 | 可验证性 | 与一手是否一致 | 处置 |
|---|---|---|---|---|
| 某本地 API 无鉴权可读明文 key | 第三方审计/L2 | 可本地复现 | 实测成立 | 补进产物并上调风险权重 |
| 某工具比 X 快数百倍 | 厂商基准/L3 | 口径不明 | 未验证 | 不引用，留待独立复测 |

### 常用入口（按优先级）

1. 仓内 `/issues`：带复现步骤的 issue 等同 L1，优先于一切媒体。
2. 通用网页搜索：定位第三方审计、横评、批评帖，关键词用「项目名 + criticism/security audit/limitations/风险」。
3. 社区讨论：HN、Reddit 相关子版，看一致/分歧而不是看单条结论。
4. 中文入口：知乎、少数派、公众号，默认按 L3 对待（洗稿与转述比例高）。
5. 辅助：star-history 只看热度趋势，不参与对错判断。

## 纠正流程（用户说「他不会这样」）

1. 只锁被指出的那一条，不重跑全流程。
2. 问一句要证据还是改口径：有原始素材就补 `[O]`；没有就降级为 `[I]` 或删除。
3. 改动后重跑 `python scripts/distill.py gate <产物>`，把版本号 +1，在文末记「纠正记录：改了什么、依据什么」。
4. 已通过三重验证的其他条目不动。

## 反臆造扫描清单（交付前逐条过）

- 有没有结论后面什么都没挂？
- 有没有把「我记得」「一般来说」当证据？
- 有没有数字来源不明（比例、星数、行数）？
- 有没有引用一个不存在的文件或路径？
- 有没有把摘要/二手转述写成原文？
- 有没有为凑篇幅补的「意义/展望」段？
- 有没有该写「未验证」的地方写了确定语气？
