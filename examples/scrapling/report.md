# Scrapling 机制：把抓取拆成四个可替换的层

## 1 它解决什么

抓取的真实难点不是「取一页」，而是四件事各自变化：有的站点要 JS、有的会挡机器人、有的字段随版本漂移、
有的要跑几千页且中途会断。它把四件事拆成四个层，任何一层可换。[O] E-9207dc44

## 2 核心机制

1. **取数分两条路。** 快 HTTP 与隐身浏览器并存，按站点难度选，而不是一套引擎打天下。[O] E-9207dc44
2. **选择器带自适应。** 除 CSS/XPath 文本正则外，还有自适应元素跟踪与相似元素匹配，
   应对「结构小改、字段还在」的常见失效。[O] E-b006b5ed
3. **爬虫可续跑。** 并发、代理轮换、重试、限速、暂停续跑与多种导出格式，把长任务当一等公民。[O] E-ffa45b5e
4. **给 agent 两种壳。** 同一能力既以 MCP 服务暴露，也以 Agent Skill 提供，终端还有 CLI 与交互 shell。[O] E-c3f3bac7
5. **反爬交互是显式能力。** 文档把 Turnstile/Interstitial 这类挑战写成支持项，而不是含糊其辞。[O] E-93eee29a

## 3 关键契约

- 「结构变了」和「站点拒绝你」是两类失败，必须分开处理：前者用自适应定位，后者换通道或换节奏。
- 导出是能力的一部分：JSON/JSONL/CSV/XML 让下游不必再写转换层，属于同一份能力清单的第四条。[O] E-ffa45b5e

## 4 失效与降级路径

| 触发 | 一线修复 | 仍失败兜底 |
|---|---|---|
| 选择器失效 | 开自适应跟踪重算定位 | 退回相似元素匹配并要求人工确认 |
| 被反爬挡 | 换隐身浏览器或调节奏 | 停手并记录被挡证据，不硬刷 |
| 长爬中断 | 用暂停续跑接着跑 | 从导出文件回填已完成部分 |
| 上下文超限 | 用 CLI 与 MCP 分流到子任务 | 只取关键字段，放弃全量 Markdown |

降级顺序按它的双形态（MCP 与 Skill）与导出能力排列。[D] E-c3f3bac7 + E-ffa45b5e

## 5 反例黑名单

- 不要把「能处理挑战」当成「授权你绕过站点规则」。
- 不要在同站点高频重试；限速与轮换是设计的一部分。
- 不要跨站点复用自适应定位结果，它是按页面结构学的。

这三条是把「能力」反用成的禁令，仓内没有对应反模式章节，标为推断。[I]

## 6 外部审视（与仓内自述的差距）

- 第三方技能安全审计对其 agent 打包形态给出负面结论：内容提供「Cloudflare 与反爬绕过的分步指引」，
  却没有任何授权或可接受使用的提示，因此「实质性促成对受保护服务的滥用」。
  本产物把这项能力写成「显式能力」，外部视角把它写成「缺警示的风险项」，两者不冲突但侧重点不同。[O] E-93eee29a
- 它的性能数字（比 BeautifulSoup 快数百倍）来自官方基准，第三方转述时直接引用；本产物刻意不引用这类自报效应量。[I]

## 7 诚实边界

- 只读 README，未跑任何抓取，所以「自适应」在真实漂移下的召回率、以及被挡率都未知。[I]
- 「可处理 Turnstile」是文档自述能力，不等于合规可用；法律与站点条款边界不在本产物判断范围。
- 一周热度不代表抓取稳定性。

## 运行安全

- 失败显式：页面结构变了靠自适应跟踪找回目标，重试与暂停续跑显式返回状态，不静默报成功 [O] E-b006b5ed
- 资源释放：隐身浏览器与 JS 渲染进程在抓取结束后释放，暂停续跑与重试统一清理连接，防子进程句柄泄漏 [O] E-ffa45b5e + E-9207dc44
