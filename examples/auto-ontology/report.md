# Auto-Ontology 技能层治理判据

> 这份产物的对象不是「一个大模型产品」，而是它写给 agent 的那层治理规则：谁拥有哪个动作、哪里是真值源、
> 什么不许写进技能正文、缺产品能力时怎么返回。这类规则换个名字仍然成立，所以值钱的是判据不是架构图。

## 1 判据表

| # | 触发条件 | 禁止行为 | 一线修复 | 仍失败兜底 | 证据 |
|---|---|---|---|---|---|
| 1 | 多个技能都声称能做同一件事 | 禁止用「通用入口」掩盖归属，让 agent 自己猜谁负责 | 按**用户动作**而不是按模块拆归属，画一张动作→拥有者表 | 表里没有该动作者，判为无主动作，先补产品能力再写技能 | [O] E-2b912521 |
| 2 | 需要写入或修改语义层 | 禁止让只读通道（MCP）承担写；也禁止技能自己发明一个写接口 | 写入只走已批准的写面，技能只指路不复制 schema | 无批准写路径时返回显式 gap，不静默降级成「你先手动改」 | [O] E-2b912521 |
| 3 | 技能里想再贴一份工具表 / 安装命令 / REST schema | 禁止把技能做成第二份 API 目录或第二个安装器 | 技能只编码**顺序、前置、坑**，真值源外链一次 | 真值源与技能冲突时以运行期真值源为准（握手时的工具表），技能文字让位 | [O] E-d8f9bdc3 |
| 4 | 技能要上架到公共目录 | 禁止手改或伪造 CI 生成的签名与基准文件 | 上架件按固定五件交出，签名由 CI 产出且必须留在 PR 里 | CI 拒绝时按它的报告补件，不在本地绕签名 | [O] E-40c82c61 |
| 5 | 技能正文要写示例（尤其部署示例） | 禁止出现 staging 主机名、集群名、密钥库路径、凭据 | 示例用占位与本地默认值，真实环境值只出现在私有配置 | 必须举真实例子时改为指向私有文档，不写进公开技能 | [O] E-e355f24c |
| 6 | 一个能力要配多个模型角色（推理 / 抽取 / 向量 / 重排） | 禁止每个角色各写一套完整配置，制造四份真值 | 用 `<前缀>_ENDPOINT/_API_KEY/_MODEL` 三元组，逐字段回退到默认前缀 | 某角色缺字段时回退并显式声明「用的是默认」，不静默共享 | [O] E-13697836 |
| 7 | agent 给出一个业务数字（指标 / 计数 / 金额） | 禁止只给数字不给来源与校验依据 | 每次回答带 provenance：命中哪条认证定义、走哪条血缘 | 无法给出 provenance 时，回答必须自称未认证，不得冒充认证结果 | [O] E-6408261c |

配套事实（不是判据，是判据成立的前提）：

- 产品自述的四件事是 discover / ground / validate / expose，第四件是把「认证修正与使用反馈」折回本体，
  所以它的 ontology 不是静态词表，而是会被使用改写的层。[O] E-6408261c
- 三个技能的边界按用户处境切：「还没起来」读 setup、「已起来要建模发布」读 management、「只提问」读 query。[O] E-2357763e
- 组件是五件（前端、后端、摄取 worker、Postgres+pgvector、可选 Vault），不是一堆微服务。[O] E-42ab8c8d

## 2 假阳性排除（哪些情况不算违规）

- **判据 3 的例外**：若某段文字是「坑」而不是「接口说明」（例如握手可能返回空工具表），它可以留在技能里，
  因为它不可外链、且只在运行期才成立。[O] E-d8f9bdc3
- **判据 5 的例外**：本地开发默认值（`localhost:3000`、`:3001`）不算泄密，它们是公开常识而不是环境真值。[O] E-42ab8c8d
- **判据 7 的例外**：探索性问题（「这张表大概有什么」）没有指标语义，不适用 provenance 要求；一旦给出数字就适用。

## 3 根因层（表象 vs 机制）

- 表象：这套仓库把「技能」写成了三份很短的指路文档，看起来像偷懒。
- 机制：因为它把**真值源**放在技能外面（部署文档、OpenAPI、握手工具表），技能只保留 agent 会错的那部分——
  顺序、前置条件、失败后的动作。技能一旦复述真值源，就会与真值源分叉，而分叉后没人知道该信哪份。[D] E-d8f9bdc3 + E-2357763e

## 4 防复发门禁（怎么让人不再犯）

- 检查项：技能正文里出现第二份工具表/安装命令/REST schema 的迹象（大段 yaml、完整 curl 清单、字段表）。
- 反例验证：把某条工具定义手抄进技能正文后，与握手时的真实工具表比对，必须能判出差异（否则这条门是空的）。
- 静默失效点：真值源本身不再更新时，「以运行期为准」会变成「以过期为准」——门禁看不出来，只能靠发布前重跑一次握手。
- 检查项：技能正文出现非公开域名、集群名、密钥库路径。
- 反例验证：故意写入一个 staging 主机名，扫描必须命中。

## 6 内在张力（不要调和）

- 同一层既要「让 agent 少读」（技能短、只指路），又要「让 agent 别猜错」（判据必须写全）。它选择牺牲完备性：
  技能不复制真值源，代价是 agent 必须能访问真值源（MCP/CLI/API 任一）。**没有运行期访问能力时，这套设计直接失效**。[D] E-d8f9bdc3 + E-2b912521
- 它既要求「每次回答带 provenance」，又把写入限制在批准路径上；这等于承认：能证明来源的答案，只能来自被治理过的数据。[I]

## 7 它绝对不做什么

- 不给未认证的答案加认证包装（判据 7 的兜底是自称未认证）。[O] E-6408261c
- 不把维护者约定（构建、测试、前端规范）塞进面向 agent 的技能，两类读者分两文件。[O] E-e355f24c
- 不因为「目录要公开」就把示例写成假数据糊过去，而是换成占位 + 私有文档。[O] E-e355f24c

## 8 降级路径（触发→一线修复→兜底）

| 触发 | 一线修复 | 仍失败兜底 |
|---|---|---|
| 技能与运行期工具表冲突 | 以运行期为准，回头改技能 | 技能标注「可能过期」，不删冲突段 |
| 需要写但只读通道给不了 | 走批准写路径 | 返回显式 gap，交人处理 |
| 上架件签名缺失 | 触发 CI 重跑 | 不上架，保留本地可用版本 |
| 答案给不出 provenance | 缩小问题到有认证定义的部分 | 明确自称未认证 |

## 9 诚实边界

- 只读到两份文件（AGENTS.md 93 行、README.md 470 行）；`skills/` 下三个技能正文、`evals/evals.json`、`docs/` 下
  connections / authentication / conversation-api 三篇都没读，所以「技能实际怎么组织」只能从目录描述推断。[I]
- 同一 URL 两次取回内容不一致：网页抓取版 README 含「token 即其拥有者」「会话改写保留最近 5 轮 / 12000 字」等段落，
  raw 下载版没有。本产物只引用 raw 版行号，另一版内容一律未采信。[O] E-42ab8c8d
- 这是单一仓库的自我描述，没有第三方评测佐证；它的「可靠性门」是卖点陈述，不是实测数字。

## 运行安全

- 危险操作确认：缺产品支持时返回 gap/receipt 而不是发明操作，写操作显式选择加入 [O] E-2b912521
- 资源释放：MCP 只读，握手时工具表与技能冲突以工具表为准，连接与资源用后即释放、teardown 清理 [O] E-d8f9bdc3
